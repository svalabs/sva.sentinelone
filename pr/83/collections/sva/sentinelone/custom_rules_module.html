sva.sentinelone.custom_rules module – Manage SentinelOne custom detection rules

Note

This module is part of the sva.sentinelone collection (version 2.3.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install sva.sentinelone. You need further requirements to be able to use this module, see Requirements for details.

To use it in a playbook, specify: sva.sentinelone.custom_rules.

New in sva.sentinelone 2.4.0

Synopsis

  • Create, update and delete site-scoped custom detection rules.

  • Rules are identified by their exact name within the selected site.

Aliases: star_rules

Requirements

The below requirements are needed on the host that executes this module.

  • deepdiff >= 5.6

Parameters

Parameter

Comments

console_url

string / required

Management console URL.

cool_off_minutes

integer

Suppress further alerts for this many minutes after the rule triggers, from 1 to 1440.

If omitted, new rules are created without coolOffSettings.

For existing rules with cool-off enabled, omission disables it by sending renotifyMinutes=0.

correlation_query

dictionary

Correlation object passed unchanged as correlationParams with queryType=correlation.

Use the API field names, including entity, matchInOrder and subQueries.

Mutually exclusive with event_query.

description

string

Rule description. Omission clears an existing description.

Default: ""

event_query

string

Single event query, passed as s1ql with queryType=events.

Exactly one of event_query and correlation_query is required for state=present.

expiration_date

string

Use Permanent for a rule that never expires.

Otherwise provide an ISO 8601 timestamp with timezone, for example 2027-03-15T10:20:00Z.

Default: "Permanent"

name

string / required

Name identifying the rule within the site.

network_quarantine

boolean

Automatically quarantine alerted endpoints.

Choices:

  • false ← (default)

  • true

query_lang

string

S1 query language version.

Choices:

  • "1.0"

  • "2.0" ← (default)

severity

string

Rule severity.

Choices:

  • "Info"

  • "Low"

  • "Medium" ← (default)

  • "High"

  • "Critical"

site_name

string / required

Name of the site in SentinelOne.

state

string

Whether the rule should exist.

Choices:

  • "present" ← (default)

  • "absent"

status

string

Desired rule status. Transitional and deletion statuses are not accepted as input.

Choices:

  • "Active" ← (default)

  • "Disabled"

  • "Draft"

token

string / required

SentinelOne API authentication token.

treat_as_threat

string

Treat-as-threat automatic response. Undefined is sent as UNDEFINED.

Choices:

  • "UNDEFINED" ← (default)

  • "Undefined"

  • "Suspicious"

  • "Malicious"

Notes

Note

  • This module can also be called as sva.sentinelone.star_rules.

  • Only single-account management consoles are supported, as with the other collection modules.

  • The API token must have permission to view and manage rules at site scope, including their logic.

  • The API exposes rules only at the token’s highest available scope.

  • Defaults are enforced on updates as well as on creation.

  • Check mode performs reads but does not modify rules.

  • Hiding rule logic is not supported. Rules with hideLogic=true were not returned by the API in live testing.

  • Do not manage names already used by hidden rules. Such rules cannot be reliably updated or deleted by this module, and their names may cause duplicate rules to be created.

Examples

---
- name: Create a single event rule
  sva.sentinelone.custom_rules:
    console_url: https://example.sentinelone.net
    token: "{{ sentinelone_token }}"
    site_name: Production
    name: Suspicious PowerShell
    event_query: 'event.type = "Process Creation" AND tgt.process.name = "powershell.exe"'
    severity: High
    cool_off_minutes: 60

- name: Create a correlation rule
  sva.sentinelone.custom_rules:
    console_url: https://example.sentinelone.net
    token: "{{ sentinelone_token }}"
    site_name: Production
    name: Repeated PowerShell execution
    status: Disabled
    expiration_date: '2027-03-15T10:20:00Z'
    correlation_query:
      entity: endpoint
      matchInOrder: false
      subQueries:
        - subQuery: 'event.type = "Process Creation" AND tgt.process.name = "powershell.exe"'
          matchesRequired: 3
      timeWindow:
        windowMinutes: 10

- name: Delete a custom rule
  sva.sentinelone.custom_rules:
    console_url: https://example.sentinelone.net
    token: "{{ sentinelone_token }}"
    site_name: Production
    name: Suspicious PowerShell
    state: absent
